# Pixel Blue 平滑自动亮度方案（替代 wluma）

> 状态：计划稿，未执行 · 2026-10-21
> 背景：PR #37（wluma 方案）经评估降级，改用自研轻量 ALS 步进 daemon

## 一、结论与决策

| 决策项 | 结论 |
|---|---|
| 替换对象 | 弃用 wluma（行为模型不透明、通用曲线无校准、外部依赖重） |
| 新方案 | 自写 ~300 行级 Python daemon：**ChromeOS eve 厂商 7 级曲线 + 官方滞回 + 指数平滑** |
| 默认行为 | **opt-in**：安装但不默认启用（去掉 user-preset），README 标注实验性 |
| 上游互动 | 不主动讨论（可选：把实测数据贴到 gsd #835，零发言贡献） |
| 参考实现 | fork/借鉴 [yabd](https://github.com/tbrugere/yabd)（iio-sensor-proxy + logind D-Bus，gamma/ramp/yield-control 齐全） |

## 二、厂商曲线数据来源（按优先级）

1. **eve 恢复镜像提取**（首选，最准）
   - 下载 `dl.google.com/dl/edgedl/chromeos/recovery/chromeos_XXXXX.eve-recovery.bin.zip`（索引：`recovery.conf` 搜 eve；eve AUE 2028，镜像仍在线）
   - 只读挂载 rootfs（GPT 第 3 分区，ext4 + dm-verity 只读不受影响）：
     `mount -o ro,loop,offset=$((起始扇区*512)) recovery.bin /mnt/chros`
   - 读取 `/usr/share/power_manager/internal_backlight_als_steps`（备选路径 `/etc/power_manager/`）
   - 格式：每行 `亮度UI% 下行阈值lux 上行阈值lux`（重叠区间 = 官方滞回）
2. **文档兜底**（镜像拉不到时）：`power_manager/docs/screen_brightness.md` 的 7 级表：
   低光 90→36.14%UI / 室内 40~250→47.62% / 室内亮 180~360→60.57% / 室外暗 250~500→71.65% / 室外阴 350~1700→85.83% / 室外晴 1100~7000→93.27% / 直射 5000→100%

**关键换算**：写背光硬件用线性值，`fraction = (percent - 6.25) / 93.75`，`level = min_visible + fraction² × (max - min_visible)`（ChromeOS 平方映射，防低亮度不可用）。

## 三、Daemon 设计

```
iio-sensor-proxy (net.hadess.SensorProxy D-Bus)
        │  LightLevel 属性变更推送（不轮询）
        ▼
指数平滑（EMA，低通滤波；ChromeOS M66 同款做法）
        ▼
7 级步进表 + 双阈值滞回（升/降阈值分离，防抖）
        ▼
缓动过渡（300~800ms ramp，避免跳变）
        ▼
systemd-logind SetBrightness D-Bus 写背光（无需 root）
```

- **曲线数据**：编译进脚本常量，或放 `/usr/lib/pixel-blue/als-steps.conf`（同 eve 文件格式，方便真机微调覆盖）
- **让位逻辑**（保留 yabd 的 yield-control）：用户手动调亮度 → daemon 暂停接管；环境光变化超过 100 lux → 收回控制（与 ChromeOS 行为一致，ChromeOS 是重启才收回）
- **与 GNOME 开关联动**：沿用 PR #37 的 `ambient-watch` 思路——`ambient-enabled` 开 → 启动 daemon，关 → 停止

## 四、相对 PR #37 的改动清单

| 文件 | 变化 |

## 五、执行步骤

- **P0 数据获取**（可先在本沙箱外验证）
  1. 下载 eve 恢复镜像，提取 `internal_backlight_als_steps` 存入仓库 `build_files/als-steps.conf`
  2. 镜像失败 → 用文档 7 级表兜底
- **P1 daemon 编写**
  3. fork yabd 骨架：SensorProxy 订阅 + EMA 平滑 + 7 级步进/滞回 + 平方映射 + ramp + yield-control
  4. 曲线外置 conf，支持真机覆盖
- **P2 打包集成**
  5. 按第四节清单改造 PR #37 分支（同分支续 commit）
  6. preset 改 opt-in，README 更新
- **P3 真机验证**（沿用 PR #37 已列清单，新增）
  7. lux 口径校准：手机照度 App 对标，微调步进阈值（Linux 侧传感器读数与 ChromeOS 原始值可能有偏差）
  8. 隐藏 ALS 后 GNOME 设置页"自动亮度"开关是否仍显示（若消失：gsettings 仍可控制，已知取舍）
  9. 手动调节 → 让位 → 环境变化 → 收回，全链路行为确认
  10. 挂起/恢复后 daemon 状态正常

## 六、风险与回退

| 风险 | 应对 |
|---|---|
| lux 口径偏差导致曲线失真 | P3-7 实测微调；曲线外置可热改 |
| 隐藏 ALS 使设置页开关消失 | 已知取舍，文档说明；或后续换"不隐藏 + 反向联动"方案 |
| Silverblue 基镜像更新破坏集成 | 组件少（1 脚本 + 1 service + 1 udev 规则），CI 构建即暴露 |
| 上游落地独立 ALS daemon / !374 复活 | 届时移除本方案回归原生，迁移成本低（仅删文件） |
| 维护负担 | opt-in 模式下用户群小而精准，bug 报告即修复清单 |
